Retrieval-Augmented Generation (RAG) - Sample Knowledge Base

What is RAG?

Retrieval-Augmented Generation (RAG) is an AI architecture that combines
Large Language Models (LLMs) with an external knowledge source. Instead
of relying only on the model’s training data, RAG retrieves relevant
documents and uses them as context before generating a response.

RAG Workflow

1.  User submits a question.
2.  Documents are loaded using a document loader.
3.  Text is split into smaller chunks.
4.  Embeddings are generated for each chunk.
5.  Embeddings are stored in a vector database.
6.  The user’s query is converted into an embedding.
7.  Similarity search retrieves the most relevant chunks.
8.  The retrieved context is sent to the LLM.
9.  The LLM generates an accurate response based on the retrieved
    information.

Core Components

-   Document Loader
-   Text Splitter
-   Embedding Model
-   Vector Database
-   Retriever
-   Large Language Model (LLM)
-   Prompt Template

Popular Vector Databases

-   Chroma
-   FAISS
-   Pinecone
-   Weaviate
-   Milvus
-   Qdrant

Benefits

-   Reduces hallucinations.
-   Uses up-to-date information.
-   Enables question answering over private documents.
-   Does not require retraining the LLM for every document update.

Example Question

Question: What is the purpose of a vector database in RAG?

Answer: A vector database stores document embeddings and performs
similarity searches to retrieve the most relevant chunks based on the
user’s query.

Sample Facts

Fact 1: OCR (Optical Character Recognition) converts scanned images and
PDFs into machine-readable text.

Fact 2: Chunk size and overlap significantly impact retrieval quality.

Fact 3: Embedding models convert text into numerical vectors that
capture semantic meaning.

Fact 4: Metadata such as filename, page number, and document source can
improve retrieval accuracy.

Fact 5: LangChain provides tools for building RAG pipelines including
document loaders, retrievers, vector stores, and prompt templates.
